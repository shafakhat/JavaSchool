Java 8-21 Features Interview Questions

Java 8-21 Features - topic bank

Topic bank #5 of the Interview Prep hub. Tutorials: Generics · Lambda & streams.

1. Why functional interfaces matter - what's the rule?

A lambda's target type must be a functional interface: exactly one abstract method (defaults/statics don't count). Four built-ins cover most needs: Function (T→R), Predicate (T→boolean), Consumer (T→void), Supplier (()→T); extend with BiX, UnaryOperator, primitives (IntFunction). Annotate your own with @FunctionalInterface to lock the contract.

2. Lambdas vs anonymous classes?

Lambdas don't create a class file per expression (invokedynamic + LambdaMetafactory), aren't objects with a class identity beyond the SAM type, and can't have state or extra methods. Anonymous classes can. this inside a lambda refers to the enclosing instance (no shadowing); performance-wise lambdas are capture-cheap and JIT-friendly.

3. Method references - the four kinds?

Type::staticMethod, instance::method (bound), Type::instanceMethod (unbound - first arg becomes receiver), Type::new (constructor). Compiler picks the compatible SAM; overloads are resolved by target type. Use when the lambda would just forward arguments.

4. Stream pipeline anatomy?

Source → zero/more intermediate ops (lazy: filter, map, sorted, distinct, flatMap, limit, peek) → one terminal op (collect, reduce, forEach, count, findAny, anyMatch). Lazy intermediate ops fuse into one pass; short-circuiting terminals (findFirst, anyMatch, limit) can skip work. Streams are single-use and don't modify the source.

5. map vs flatMap?

map: 1→1 transformation. flatMap: 1→N, flattens nested structures: orders.stream().flatMap(o -> o.items().stream()). Common bug: using map and ending up with Stream<Stream<T>> or Stream<List<T>> when a flat pipeline was wanted.

6. Are parallel streams safe? When would you use them?

Only if: the source is cheaply splittable (ArrayList, arrays, IntStream.range), elements are independent, no shared mutable state (or use collectors), operations are CPU-bound, and the input is large enough to beat the fork/join overhead. Never for I/O, small collections, or order-hostile-to-cost hotspots; they share the common ForkJoinPool - a blocking task can starve the app.

7. Stateful vs stateless lambdas in streams?

Stateless (map/filter functions pure) is safe and parallel-friendly. Stateful: limit, sorted, distinct (buffering), and mutations in peek/forEach (undefined with parallel). Rule: no side effects in intermediate ops; collect results, don't mutate from forEach unless that is the goal.

8. Which collector for which job?

toList/toSet, toMap (needs merge function on duplicates!), groupingBy (+downstream: counting, mapping, summingInt, averagingDouble, teeing), partitioningBy (always two keys), joining (text), teeing (two collectors in one pass, 12+). toMap with duplicate keys throws IllegalStateException - supply (a,b)->b.

9. Optional: what it's for and the anti-patterns?

For return types where absence is a normal outcome (not fields, parameters, or collections - use empty ones). Anti-patterns: isPresent()+get() (use map/orElse/orElseGet/ifPresentOrElse), Optional of collections, Optional as a Map value, get() without a check, and Optional in hot loops (allocation). Methods: map, flatMap, filter, or, stream (9+).

10. Interface evolution: default, static, private methods?

default methods add behavior without breaking implementors; static methods hold utilities (Comparator.comparing); private (9) methods share code between defaults. Conflict resolution: class wins over interface; unrelated defaults require an explicit Interface.super.m() call.

11. What are modules (JPMS) really solving?

Strong encapsulation (internal packages invisible: sun.misc etc.), reliable configuration (declare what you need), smaller runtime images (jlink), and faster startup for big apps. Cost: migrating reflection-heavy frameworks (opens flags), split packages, and classloader tricks become explicit. Most apps today use them transitively via JDK internals.

12. What's new in the java.time API vs Date/Calendar?

Immutable, thread-safe, fluent: LocalDate/Time/DateTime, Instant, Duration/Period, ZonedDateTime/ZoneId, formatters, adjusters, and clock injection for tests. Old Date/Calendar: mutable, 0-based months, broken timezone handling, SimpleDateFormat not thread-safe. Convert with Date.from(instant) etc. at boundaries.

13. What changed in the collections API in 9/10/11/21?

9: immutable factories List.of/Set.of/Map.of/Map.ofEntries (+ copyOf), Stream.ofNullable. 10: Collectors.toUnmodifiableList, List.copyOf. 11: toArray(IntFunction), Predicate.not. 16: Stream.toList. 21: sequenced collections - getFirst/getLast/addFirst/addLast/reversed on List/Deque/SortedSet, and List.reversed() views.

14. Text blocks and template strings?

Text blocks (15): multi-line literals with incidental-indent stripping. Template processors (21 preview): STR."Hello \{name}" with pluggable sanitizing processors (FMT, SQL, JSON) - the key point: interpolation can be safe because the processor validates, unlike naive concatenation.

15. Records versus Lombok versus plain classes?

Records: language-level, transparent data carriers, final components, pattern-matchable, zero dependencies; no inheritance, no builder, no mutable state. Lombok: annotations for builders, mutable POJOs, JPA entities. Plain classes: full control. Choose records for DTOs/value objects; Lombok/dependency for ORM entities and complex builders.

16. Sealed types and exhaustive switches?

sealed interface Expr permits Add, Mul, Num + final/record subtypes give the compiler a closed world: pattern switches can be checked for exhaustiveness without default, enabling safe algebraic-data-type modeling (ASTs, commands, results) with compiler-verified completeness.

17. What is pattern matching (instanceof → switch) fixing?

Boilerplate casts and manual chains: if (o instanceof Point p && p.x() > 0) instead of cast-after-check. Switch patterns handle type, null (case null), guards, record deconstruction (case Point(int x, int y)), and enum+type mixes - all with flow scoping of the bound variables.

18. What did Java remove/deprecate that interviewers still probe?

Removed: finalize (18), SecurityManager (deprecated for removal), Thread.stop/suspend, Nashorn (15), CORBA/JAXB/activation modules (11), CMS GC (14). Deprecated: Applet API, Runtime.exec patterns, Date constructors, stack of old I/O (use NIO), System.runFinalizersOnExit.

19. New in I/O: NIO.2, Files helpers, transferTo?

NIO.2 (7): Path/Files, walking, watching, async channels. 9-12 additions: Files.readString/writeString, InputStream.transferTo/readAllBytes (9), Files.mismatch (12), FileChannel.transferTo zero-copy. Modern rule: for text, readString/writeString; for big data, stream with buffered channels, never read the whole file unless it fits memory.

20. New in HTTP: what replaced HttpURLConnection?

java.net.http.HttpClient (11): HTTP/2 + WebSocket, async/sync APIs, CompletableFuture, immutability, no global state. Virtual-thread friendly. Third-party alternatives still win for HTTP/1.1 quirks and connection tuning (OkHttp, Apache HttpClient). Key interview point: never use URLConnection for new code.

21. What is the HttpClient/Flow (reactive streams) story?

java.util.concurrent.Flow (9): Publisher/Subscriber/Subscription/Processor - the JDK's reactive-streams interfaces, used by HttpClient body handlers and adapters (RxJava, Reactor, Akka interop). It's the standard contract that libraries implement; you rarely implement it directly.

22. What are the biggest changes in Java 17-21 for application code?

14-16: switch expressions, text blocks, records, instanceof patterns. 17: sealed types, always-strict floating point. 18-20: UTF-8 by default (18), simple web server (18), virtual threads + structured concurrency (preview→final in 21), FFM API previews. 21: pattern switch, record patterns, sequenced collections, virtual threads, generational ZGC.

23. How do you upgrade an old codebase - practical order?

Pick an LTS target; fix deprecations compiler-visible first (-Xlint:all, --release), replace removed APIs (finalize→Cleaner, SecurityManager→alternatives), update build plugins, run tests on each LTS hop when jumping far (8→11→17→21), watch GC/flag changes (CMS removed), and check libraries' module/open needs. Automate with jdeps and CI matrix runs.

24. Which features are still preview in 21 and why avoid shipping them?

Structured concurrency, scoped values, string templates, FFM API (21), unnamed patterns/variables. Preview = API may change or vanish; requires --enable-preview, cannot easily ship in libraries. Use for experiments/spikes, abstract behind your own façade, and revisit at the next LTS.

25. Interview favorite: rewrite this with streams - for loop building a map of department → average salary.

emps.stream().collect(groupingBy(Employee::dept, averagingDouble(Employee::salary))) - then explain: the loop version is fine too; streams buy declarative clarity (and are worth it when combining filter/map/grouping), not raw speed. Mention parallel only with justification, and null handling (filter Objects::nonNull first).
