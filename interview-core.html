Core Java & JVM Interview Questions

Core Java & JVM - topic bank

Part of the Interview Prep hub. Cross-reference: Master list (115), Java basics tutorial.

1. Walk through what happens between writing Hello.java and seeing output.

javac parses, type-checks and emits Hello.class (bytecode + constant pool). java starts a JVM, the launcher finds the class via class loaders, the verify step checks bytecode safety, static initializers run, then main executes on the first thread. JIT compiles hot methods later.

2. Which class loader loads my Hello.class?

The application class loader (child of the platform loader, whose parent is the bootstrap loader). Delegation model: child asks parent first (so java.lang.String can't be spoofed), then tries itself. Custom loaders override findClass/loadClass - web containers use them for per-app isolation.

3. What lives in Metaspace vs the heap vs the stack?

Metaspace (native): class metadata, method tables, constant pool of loaded classes. Heap: objects + arrays, shared. Stack (per thread): frames - locals, operand stack, return addresses. Direct buffers and JIT code cache are separate native regions.

4. Young vs old generation - why does it exist?

Most objects die young (weak generational hypothesis). Eden + survivor spaces collect short-lived objects cheaply with copying; survivors promote to the old gen, collected less often by major GC. This split is why System.gc() pressure and allocation rate matter.

5. STW vs concurrent vs parallel GC - the vocabulary?

Stop-the-world: all app threads paused (any GC phase that needs them halted). Concurrent: marking/cleanup runs alongside app threads. Parallel: GC work spread over multiple cores. G1 does mostly-concurrent marking with parallel evacuation; ZGC/Shenandoah aim for sub-ms STW.

6. What triggers a full GC?

Old-gen pressure / promotion failure, System.gc() (a hint; -XX:+DisableExplicitGC ignores it), some metadata pressure (Metaspace), CMS-era counterparties (now gone), and jmap/heap-dump requests. Signals: old-gen near-full after GC, rising full-GC frequency, allocation stalls.

7. Constants: literal, static final, enum - differences?

Compile-time constants (static final of primitive/String with constant initializers) are inlined into callers - changing one recompiles dependents. Non-compile-time static final (e.g. new Date()) initialized at class init. Enums are objects with identity, safe serialization and switch support.

8. Final, finally, finalize - one line each.

final: constant reference / no override / no extend. finally: always executes (try-with-resources preferred). finalize(): deprecated (9), removed path (18) - never relied on it; use Cleaner or explicit close.

9. Instance vs static vs local variables - defaults and lifetimes?

Instance: default values (0/false/null), live as long as the object. Static: class-level, default values, initialized in static blocks. Local: no default - definitely-unassigned rule; stack-confined, lifetime of the frame.

10. Widening vs narrowing conversions - where do casts matter?

Widening (byte→short→int→long→float→double) is implicit. Narrowing needs an explicit cast: int i = (int) bigLong; - may lose bits. Numeric promotion happens in expressions (byte + byte → int). Reference narrowing needs the compiler to allow it (downcast) and may throw ClassCastException.

11. Short-circuit vs bitwise operators?

&&/|| skip the right side when the answer is known - guards null checks: o != null && o.ok(). &/| evaluate both (and work on booleans too). ^ is XOR (non-short-circuit).

12. Ternary operator traps?

The branches' types unify (often promoting int/Double oddly); a reference branch can yield null silently; nested ternaries without parens destroy readability. Assignment inside a ternary condition compiles but is banned by most style guides.

13. Switch pitfalls?

No fall-through with arrow form (case A ->), classic : form falls through unless break - the classic bug. Switch works on int/char/enum/String (since 7, via hashCode). Pattern switch (21) adds types + guards (case Point p when p.x() == 0).

14. == on boxed Integer > 127?

Integers cache -128..127; beyond it == compares references → Integer.valueOf(200) == Integer.valueOf(200) is false while the same with 100 is true. Always use equals/Objects.equals for wrappers. (Cache bounds configurable via XX:AutoBoxCacheMax.)

15. Autoboxing NPEs?

Integer x = null; int y = x; → NPE at unboxing. Also Map.get into a primitive, ternaries mixing null and primitives, and collections of wrappers in arithmetic. Unboxing is inserted by the compiler - the NPE line looks like plain assignment.

16. For vs for-each - when can't for-each be used?

for-each covers arrays and Iterable. You need a classic for (or iterator) for: index access, modifying the collection, simultaneous iteration of two collections, first-match with early exit plus position, or while with explicit remove.

17. What does static mean for inner classes?

A static nested class doesn't hold an implicit reference to the outer instance (no Outer.this) - cheaper, no leak. Non-static inner classes can directly touch outer members but pin the outer object (common leak with long-lived inner instances in activities/threads).

18. Nested vs inner vs local vs anonymous classes?

Nested static: no outer reference. Inner: has Outer.this. Local: declared inside a method - can be final/effectively-final. Anonymous: one-shot new Interface() {...} - now usually replaced by lambdas (unless you need multiple methods/state).

19. Can you initialize a field in a static block AND declaration? Order?

Yes - static initializers and static field declarations run in textual order at class init, once, guarded by classloader locking. Circular static references can expose default values (the "initialization order" gotcha). Instance side: fields → instance initializers → constructor.

20. What are varargs - hidden costs?

Object... is sugar for an array; each call allocates the array (unless passing an existing array). Overload resolution prefers non-varargs; generic varargs → heap pollution warning (@SafeVarargs for trusted generic/final methods). Printing via String.format is fine; tight loops should avoid it.

21. String concat in loops - what did the compiler ever do for us?

Since Java 9 (indy): a + b compiles to makeConcatWithConstants invokedynamic - one mutable StringBuilder-like strategy per call site, reused. Pre-9 javac created new StringBuilders per iteration. Either way, huge concatenations → build explicitly with StringBuilder for clarity and control.

22. What is the diamond problem in exception handling here?

catch (Exception) after catch (IOException) - unreachable checked handlers compile-error for unrelated checked types; multi-catch A | B can't catch subclasses of each other. Order matters: specific first, general last.

23. assert - use and misuse?

assert expr : msg throws AssertionError when disabled expressions... no: assertions run only with -ea; without it the expression is skipped entirely - never put side effects in them. For production validation use explicit if + exceptions.

24. Enum singleton vs classic singleton - why is enum preferred?

Enum constants are created by the JVM once: immune to reflection instantiation (constructor throws), serialization-safe by default (readResolve is built in), concise. The holder-pattern singleton is the other acceptable form; anything with if (instance == null) needs synchronization to be correct.

25. What makes a class immutable - checklist?

final class; final fields; no setters; constructor does all setup without leaking this; defensive copies for mutable inputs (get clones or returns unmodifiable views); all fields privately owned. Benefits: thread-safe without locks, safe hash keys, easy reasoning. Records automate much of it.

26. What is transient + custom serialization hooks?

Skip fields from default serialization; hooks writeObject/readObject (per-field), writeReplace/readResolve (substitute instances - singleton protection), Externalizable (full control, no-arg ctor required). serialVersionUID pins compatibility.

27. Clone: shallow vs deep?

clone() copies primitives and references (shallow) - shared mutable subobjects. Deep copy: serialize round-trip, constructor copy, or manual field-by-field. Arrays: clone() is one level; Arrays.copyOf same. Modern alternative: copy constructors / records with copying factories.

28. Why does new of a generic array fail?

Erasure - new T[] impossible: JVM can't know T at runtime. Workarounds: ArrayList, Arrays.asList(new T[0]) cast trick (with unchecked warnings), or pass a factory. Arrays are reified (runtime component type) - that's the whole source of generic-array pain.

29. What is the difference between Comparable natural order and a Comparator passed to sort?

Natural order is baked into the class (compareTo) - one per type. Comparator is an external strategy - many orders, composable (thenComparing), can fix types you don't own. If both exist, TreeMap needs explicit comparator in the constructor to override natural order.

30. Reading a properties file - correct modern approach?

Load via Properties.load with try-with-resources (ISO-8859-1 historically; Java 9+ reader over UTF-8 ok) or use Jackson/YAML/Typesafe config. getProperty returns String only - parse with defaults: Integer.getInteger is system-properties, not file - don't mix them up.

31. How would you make equals for a class with inheritance?

Instanceof-based (null-proof, subclass-tolerant) when the contract allows polymorphic equality; getClass() == o.getClass() for exact-type equality. Never let a superclass compare fields a subclass ignores (violates symmetry) - that's why abstract bases either don't implement equals or define it per final class.

32. What does hashCode have to do after equals changes?

Nothing automatic - you maintain it. Equal objects must return the same hash every time they're equal; changing equals-relevant fields while the object is a HashMap/HashSet key orphans it (bucket lookup uses the old hash). Rehash explicitly: remove, mutate, re-add.

33. What is the difference between RuntimeException hierarchy and checked?

Checked = compile-time contract (catch or declare), for expected recoverable conditions. Unchecked = programming errors & JVM conditions. Arguments: effective Java prefers unchecked for most cases where callers can't act; APIs keep checked where no sensible default exists (IOException on a file API).

34. What will System.out.printf formatting traps catch?

%d on a float → IllegalFormatConversionException at runtime; locale-sensitive grouping (%,d); %n vs \n (platform line separator); argument index reuse (%1$s). Format strings are compiled per call - reuse the string, not the layout logic, in hot code.

35. Defensive copying in APIs - where exactly?

At both boundaries: copy incoming mutable objects in constructors/setters (before storing), and return copies (or unmodifiable views) from getters - otherwise callers mutate your state and your immutability claim is fiction. Cost is fine for small objects; for big buffers consider read-only facades.
