Java Comments

Three kinds of comments

Java supports three comment styles. The compiler ignores all of them.

TypeSyntaxTypical use
Single-line// textExplanations on one line
Multi-line/* text */Longer notes, temporarily disabling code
Javadoc/** text */API documentation generated by the javadoc tool
CommentTypes.java
public class CommentTypes {
    // 1. single-line comment
    public static void main(String[] args) {

        /* 2. multi-line comment
           can span as many lines as you like */

        /** 3. Javadoc comment - shows in generated docs
         *  and in IDE tooltips */
        System.out.println("Comments are invisible to javac");
    }
}

Single-line comments

SingleLine.java
public class SingleLine {
    public static void main(String[] args) {
        int price = 500;          // in rupees, before tax
        int tax = price / 10;     // 10% flat tax
        System.out.println(price + tax);
    }
}

Multi-line comments

MultiLine.java
public class MultiLine {
    /*
     * Legacy discount rules retired in 2025.
     * Do not re-enable without finance sign-off.
     */
    public static void main(String[] args) {
        System.out.println("Active rules only");
    }
}
⚠ Warning Multi-line comments do not nest. A /* inside a block comment does not start a new one - the first */ closes everything.
NestingTrap.java
/*
  /* inner comment looks nested but is not */
*/
// Everything above is commented out... but the first */ already ended it,
// so the next line is LIVE code again - and may not compile.

Javadoc comments

Javadoc starts with /** and supports tags like @param, @return, @throws:

Circle.java
public class Circle {
    private double radius;

    /**
     * Creates a circle with the given radius.
     *
     * @param radius the radius, must be positive
     * @throws IllegalArgumentException if radius <= 0
     */
    public Circle(double radius) {
        if (radius <= 0) {
            throw new IllegalArgumentException("radius must be > 0");
        }
        this.radius = radius;
    }

    /** @return the area of this circle */
    public double area() {
        return Math.PI * radius * radius;
    }

    public static void main(String[] args) {
        Circle c = new Circle(2);
        System.out.println(c.area());
    }
}

Running javadoc Circle.java produces browsable HTML documentation from those comments - this is how JDK documentation itself is produced.

Commenting style that ages well

  • Why, not what. int age = 25; // sets age to 25 adds nothing. Explain the reason: // under-25 surcharge applies.
  • Keep comments updated - a wrong comment is worse than none.
  • Use comments to mark TODOs consistently: // TODO: handle empty list.
  • Comment the public API with Javadoc; leave internal details as // notes.
GoodComments.java
public class GoodComments {
    public static void main(String[] args) {
        int retries = 3;
        // 3 attempts: gateway tolerates 2 failures before failing over
        while (retries > 0) {
            System.out.println("attempt " + (4 - retries));
            retries--;
        }
    }
}

Temporarily disabling code

Disabled.java
public class Disabled {
    public static void main(String[] args) {
        System.out.println("active line 1");
        /*
        System.out.println("disabled line 2");
        System.out.println("disabled line 3");
        */
        System.out.println("active line 4");
    }
}

Prefer commenting out small regions only - large commented-out blocks rot quickly. Version control exists; delete-and-restore is free.

🚀 Tip Most IDEs toggle comments with a shortcut - Ctrl+/ (Windows/Linux) or Cmd+/ (macOS).
